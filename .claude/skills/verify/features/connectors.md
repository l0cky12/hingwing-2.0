# Connectors

A small grid-plus button named Connectors sits at the right of the sidebar's foot, beside the Hermes row, in bot mode, chat mode and the compact bots column. It, or Ctrl+Shift+M (Cmd+Shift+M on a Mac), opens the Connectors screen in place of the chat, as Tasks does, and the sidebar stays. The screen belongs to the open chat's bot, which "Configuring:" names at the top right. Five tabs sit at the top left, each with a count once Hermes answers: Skills, Plugins, Connectors, Tools and Templates, with Connectors chosen. The Left and Right arrows move between the five tabs and wrap at either end. Escape, Close or Ctrl+Shift+M again go back to the chat and put focus back where it was. Opening another bot or chat from the sidebar closes the screen.

The Connectors tab has a search field ("Search N connectors") that narrows the cards by name, an "Add your own" button that opens the add-a-tool-server form [Tool servers](./tool-servers.md) covers, and All, Added and Available filters that count the cards the search leaves. Under them, an Added section and an Available section, each with its count, lay their cards out two to a row, and one to a row in a narrow window. Added holds every app with an account, whatever its standing, and every tool server. Available holds every app with no account, Recommended first. An app card shows "App · <category>", its description, and Connected, Needs sign-in again, Disconnected or Available. Connect and Reconnect open the sign-in page in the browser, the card says Connecting…, and Open sign-in again opens that same page if the wait stalls. The card then shows the new standing and moves to its section. Remove drops an account. A tool server card shows "MCP · Custom" or "MCP · Plugin", its address or command, and its state.

The Skills tab lists the bot's skills with a switch each ("Use <name>"). The Plugins tab's installed plugins each have a switch ("Use <name>"). It works as the Skills switch does: a flipped switch shows the new state, disabled, until Hermes answers, and a refusal puts it back and says why under the cards. While one switch waits for Hermes, the tab's other switches are disabled too, so changes go one at a time. A plugin is switched by its canonical key. Turning a plugin off always waits for Hermes to restart, as Hermes reports it, and so does turning on a plugin Hermes cannot load at once: the card then says "Takes effect when Hermes restarts." under its description. A Hermes that can't switch plugins says "This Hermes can't turn plugins on or off." after the first try, and every plugin switch stays disabled. The Tools tab lists the toolsets of the bot the screen shows, each with Hermes's label, its description and a switch ("Use <label>"), and says "Changes reach each of <name>'s chats from its next message. Group chats keep the tools they started with." A toolset that is not for the chat names its platform, such as Discord, beside its label. A switch writes only that bot's config over Hermes's HTTP API, and touches no chat, so the open chat keeps its conversation. (Hermes's `tools.configure` rebuilds the chat's agent and forgets its conversation, so Highwing never sends it.) It works as the plugin switch does. A Hermes with no toolset routes, or whose routes refuse the bot, lists the chat's toolsets read-only as `tools.list` answers them, each with its description, its first five tools and how many more, and "On · N tools" or Off, with a note that says why there are no switches: "This Hermes can't switch toolsets from Highwing." Serve the routes with `--toolsets fixtures/tools/switches.json`.

The Plugins tab lays out like the Connectors tab: a search field ("Search N plugins") that matches a plugin's name, description, category or maintainer, and All, Added and Available filters with counts. Added holds the plugins Hermes has for the bot, each with "v<version> · <source>", its description and its switch. Available holds the plugins in Hermes's public plugin catalog that the bot doesn't have, by catalog name or name: official, then verified, then community, each by Nous's featured rank, then stars, then name. Main reads the catalog from the web when the screen opens, and keeps it 30 minutes. While it loads the tab says "Loading Hermes's plugin catalog…". If it fails, Added still shows, with "Highwing couldn't load Hermes's plugin catalog." and Try again. An Available card shows "<Tier> · <category>", with the platforms it is limited to, such as macOS, and its description. Both sections draw each card's tile at 2:1, 104x52, where the other tabs draw 36x36. A tile shows the plugin's art from the catalog, an Added card's looked up by its catalog name or name, fitted inside the tile on its paper. Only art at an https address on raw.githubusercontent.com, github.com or another githubusercontent.com host is used. Main fetches it as it fetches a web image in a chat, and refuses an SVG. A tile asks for its art only once the card is on screen, and keeps it after. It is blank while the art loads, and shows the plugin's first letter when there is no art or it fails to load. Available shows 60 cards, and Show more adds 60. Install ("Install <name>") asks first inside the card: it shows the repository and "It runs on Hermes's computer.", plus "Community plugins come from independent developers." for a community plugin, with Cancel and Install. The card then says Installing…, and every other Install waits. After the install the plugin moves to Added, and a status line says "Installed <name>.", with "Restart Hermes to finish." or the settings it needs. A refused install shows Hermes's words as an alert. The tab lists the plugins again after every install, refused ones too, since Hermes places a plugin before it turns it on and a refused enable leaves it installed and off. If that list can't be read, the alert says so. The tab's count stays the installed count.

The Templates tab always shows 3, and the header hides "Configuring:" there, because a template makes a new bot. [Bot templates](./bot-templates.md) covers it.

## Sub-features

- `cx-after` opens the screen from the bot foot in dark at 1440x900 and shows each of the first four tabs with its count, and the Templates count.
- `cx-connect` searches, filters, connects GitHub, removes Slack, and closes and opens the screen with Escape and Ctrl+Shift+M.
- `cx-chats` opens the screen from the Chats column in light, reconnects Notion and closes it with Close.
- `cx-compact` opens it from the compact bots column.
- `cx-skill` turns a skill on, and shows the plugins and the tabs' arrow keys.
- `cx-tools-new` reads the toolsets with an unstarted new chat open.
- `cx-tool-switch` switches two of Emu's toolsets, then one of Research's, and each switch names only the bot the screen shows.
- `cx-old-tools` shows a Hermes with no toolset routes: the read-only list and why it has no switches.
- `cx-plugin-switch` turns a plugin on and off, and shows the restart note.
- `cx-old-switches` shows a Hermes that lists plugins but can't switch them.
- `cx-old-hermes` shows a Hermes with none of the calls.
- `cx-plugin-install` searches the catalog, installs mem0, and has pomodoro's install refused.
- `cx-plugin-art` shows the catalog's art on Added and Available cards, and the letter where art is off GitHub, an SVG or missing.
- `cx-plugin-art-lazy` shows that a card asks for its art only once it is shown: on the Plugins tab, and in view.
- `cx-plugin-catalog-fails` shows the installed plugins when the catalog can't load.

## How to get to it (user POV)

- Click the grid-plus Connectors button at the bottom right of the Bots or Chats column. Its tooltip names the shortcut.
- Press Ctrl+Shift+M. It does nothing while a dialog or Settings is open, and the first-run screen has no such shortcut.
- Settings' Keyboard shortcuts page lists the shortcut as Connectors.

## Gotchas

- Every tab's panel stays in the page while hidden, so `see` can match a hidden tab's text first and time out. Prefer `count`, `called` or a name only the shown tab has.
- `count` checks at once. After a Remove, wait with `gone` on the removed control before counting the card in its new section.
- The sign-in settles on the second status read, about 800 ms after the click. GitHub is proven by Reconnect GitHub and the Available section gone.
- `opened browse` wants exactly one browser open in the run, so a run that both connects and reconnects fails that step.
- `--connectors` answers `connectors.connect` itself, so a story that waits on that call does not advance. `fixtures/errand.jsonl` does not wait on it.
- The in-turn sign-in card is a different surface. These runs do not open it.
- A recipe that installs must name `--plugins` too: the gateway plays `plugins.manage` only when the header lists plugins. The first Install click asks, and the second, on the same name, installs.
