# Servers and ways in

Settings > Connection holds every Hermes server Highwing remembers, and several ways in to each. A server with one way shows the card [Settings](./settings.md) describes, with two text buttons under it: "Add a way in" and "Add a server". Each opens the card's editor. The editor's first row says what it is for: "Where Hermes runs" from Change, "Another way in to <server>" from Add a way in, and "Where the other Hermes runs" from Add a server. Its kinds are Tailnet machine, SSH, Web address and This computer. SSH asks for an "SSH destination", such as a LAN address or a host of the SSH config, and its check runs ssh and then Hermes without asking Tailscale. Add a way in starts on the first kind the server has no way of.

A check that passes from Add a way in keeps the chat as it is and says "<server> can now be reached over <label>." The card then shows a "Pick" row, Fastest or In order, and one row for each way in priority order: its label (Tailscale, LAN, SSH, Web or This computer), its address in mono, how long it took to answer when it was last timed, or "No answer", an "In use" pill on the way the connection goes through, Move up, Move down and Remove. Change is gone while the server has two or more ways. Each dial times every way. Fastest dials the way that answered soonest, and a way within 5 ms of it wins when it is higher in the list. In order dials the first way that answered. A way that did not answer is still dialed, after those that did. When a dial fails, the next way is dialed. After an edit of the ways Highwing times them again, and reconnects only when another way would now be picked. Removing the way in use reconnects through a way that is left.

A check that passes from Add a server saves the new server beside the others and moves the chat to it. With two or more servers a "Servers" list sits above the card: each server's name, its ways' labels, "In use" on the current one, and Use and Remove on the others. Use moves the chat to that server and says "Highwing now uses the Hermes on <machine>." The server in use cannot be removed. Every edit is saved to `connection.json` before anything else changes, and holds across a restart. While a check runs, every Move, Remove and Use button and the Pick are off.

## Sub-features

- `way-add` shows one server with one way as before plus the two text buttons, opens Change with its four kinds, adds the LAN way, and sees LAN picked as the fastest.
- `ways` opens on a server saved with the Tailscale way and the LAN way: LAN is In use, each row shows its time, and the first Move up and the last Move down are off.
- `ways-order` switches to In order, which moves the connection to the first way, then moves LAN up, which moves it back. The order and the pick hold across a restart.
- `way-remove` removes the way in use, and the connection goes on through the way that is left, with Change back.
- `fallback` opens on a server whose first way answers nothing: its row says "No answer", and the second way is In use.
- `server-add` adds this computer as a second server, which becomes the one in use, and the first server is listed with Use and Remove.
- `server-use` switches to the other server and back, and the pick holds across a restart.
- `server-remove` removes the server that is not in use, and the Servers list goes with it.
- `ways-search` finds the Connection page by "fastest".
- `ways-narrow` keeps every button of the ways and the servers inside the card in a 360 px window.
- `walkthrough` records a video of adding a LAN way, the pick moving to it, In order, a reorder, a second server and a switch between the two.

## How to get to it (user POV)

- Open Settings from the Hermes button at the foot of the sidebar, or with Ctrl+Comma. Connection is the first page.

## Gotchas

- The fake machine answers ssh at two names, `hermes-host.example-tailnet.ts.net` and `192.168.1.20`, and its Tailscale lists only the first. A Tailnet machine check of `192.168.1.20` fails as "No machine called 192.168.1.20 is on your tailnet", which is right. Add it as SSH.
- A time is how long one `ssh <host> exit` took: the fake ssh waits 120 ms at the tailnet name and 15 ms at the LAN address, and starting the fake tool adds about 40 ms to both. Do not assert a time. Assert which way is In use, with `wait via-lan` or `wait via-tailnet`.
- `wait via-lan` and `wait via-tailnet` pass only while the Connection page lists the ways and the link is online, so they also wait out the reconnect an edit starts. A server with one way has no rows, so neither state ever shows for it.
- A way row's buttons are named by its address: "Move 192.168.1.20 up", "Remove 192.168.1.20". A server row's are named by the server: "Use hermes-host", "Remove This computer". A bare "Remove" names nothing.
- The top bar and the Hermes button name a server with several ways by its name, so a server saved as `ways` or `servers` reads "on hermes-host" whichever way is in use. A server with one way is named by its machine, as before.
- Both servers of `--saved servers` reach the one fake gateway: the fake `hermes` on this computer and the fake `ssh` mint from the same fixture. The chats are the same on both, so prove a switch by the machine's name, not by a chat.
- A switch of servers starts a new epoch, which remounts the window, as a passed Change does. Focus then lands on the button the news belongs to: Change after Use, and "Add a server" after an added server.
- No run reaches a refused save. `apps/desktop/test/connection.test.ts` covers a pick and a reorder whose save fails, and the card shows main's reason under it.
