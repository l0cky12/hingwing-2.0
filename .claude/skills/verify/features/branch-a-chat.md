# Branch a chat

The user points at one of their sent messages, chooses "Branch from here", and gets a new chat that holds the conversation through that message's reply. It opens at once with the message's text in its box, focused with the caret at the end, so the user can change it and send. That text is the new chat's draft, so it stays with the chat across a switch, and the Chats list marks the row "Draft". The chat they branched from stays as it was, and its row stays in the Chats list. Hermes titles the new chat next in the lineage ("Notes heading #2"). The choice sits in the More menu ("More actions", ⋯) of the message's action row, after "Copy request" and "Edit message", on every sent message that has a stored row. While a branch cannot start, that is while a turn runs, while a message waits to be sent, and while the chat is not live, More is disabled. A Hermes that cannot branch is refused in words under the composer, and the open chat does not change.

## Sub-features

- `branch-button` puts "Branch from here" in the More menu after "Edit message" on each sent message that has a stored row, and on no message that is still sending.
- `branch-open` opens the new chat at once. Its thread holds the requests and replies through the one branched from, and its box holds that request's text, focused, as the chat's draft.
- `branch-parent` leaves the original chat with all its turns, and lists both chats.
- `branch-title` names the new chat next in the original's lineage, in the top bar and the Chats list.
- `branch-refused` shows "This Hermes can't branch a chat." for a Hermes without branching, keeps the original chat open and its box empty.
- `branch-compacted` shows "Hermes compacted this part of the chat, so it can't branch from here." for a message from before a compaction, and keeps the original chat open.
- `branch-disabled` disables More while a turn runs.

## How to get to it (user POV)

- Hover a sent message, press ⋯ ("More actions") and choose "Branch from here".

## Driving it with highwing-verify

Preconditions:

- `fixtures/branch.jsonl` and `fixtures/branch-old.jsonl`, written by `python3 fixtures/make_edit_fixtures.py`. Both are the edit chat: three stored turns, rows 1 to 6, titled "Notes heading", with no steps. `branch` says in its header that Hermes branches, so the gateway answers a `session.mutate` branch itself: it copies the stored rows through the row asked for into a new chat of the same profile, and the chat answers a message with `default: <text>`. `branch-old` has no such flag, so the gateway refuses the operation `invalid_params` with no field, as an older Hermes does.
- `fixtures/branch-compacted.jsonl`, from the same script, is `branch` after Hermes compacted the first turn. Its stored rows hold a compaction row after the first reply. The gateway leaves it out of the resume's `display_messages`, as Hermes does, so the thread shows no notice, and keeps it in `session.transcript`. It refuses a branch through a row before it `invalid_params` with no field, as Hermes does for a row that is not active, and Highwing then reads the transcript to tell that refusal from a Hermes without branching.
- Every thread has one "More actions" per sent message. Use `click-at` and `disabled-at` with the message's number, counting from 1, then `click menuitem "Branch from here"`.
- The running-turn check uses `fixtures/edit.jsonl`, whose story holds a two second tool step.

The thread, the heading and the empty box are the original's.

The running turn has no button, because Hermes names its message only in the completion receipt, and the first turn's button is disabled until the reply settles.

## Gotchas

- The branch fixtures have no steps, so a message sent in the original chat would fail the story. Send in the new chat instead: its gateway answers `default: <text>`.
- More shows on hover or focus, as Copy and the pencil do. The ARIA snapshot lists it, and lists the menu item only while the menu is open.
- The three actions hang in the margin beside a request, and the request keeps 104px for them. With less, the actions run past the thread and the default 1180px window shows a horizontal scrollbar in a shot.
- The gateway does not read the row beyond checking that the chat has it. Assert the cut with `called ... "through_message_id":4`.
- The window keeps the key it minted for a message until Hermes answers, so a click after a dropped connection sends the same request and gets the same chat. An answer, whether a success or a refusal, makes the next click mint a new key.
- The scripted gateway forgets a branched chat when its run ends. A second run with the same name loses the new chat, and the draft sweep then deletes its draft, as it does for any chat that is gone.
