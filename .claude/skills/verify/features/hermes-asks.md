# Hermes asks

Hermes can ask the people watching a chat for a sudo password, a secret, a vault's master password, a login to save, a one-time code, a batch of questions or a connector sign-in. Each gets an amber card at the live end, and each closed request leaves one line in the past tense. A sudo password, a secret, a vault password, a login and a code share one card with its fields, a decline button and a send button. What is typed goes to Hermes in the reply and nowhere else: not the thread, the find index, a log or a recording. A batch of questions, or a plugin command's one choice, is answered one question at a time. A connector card lists each target with its sign-in link, **Connect** and **Skip**. A request for part of Hermes Desktop's own window, such as its theme picker, is refused at once while the window shows the chat, and the thread says so in one line.

## Sub-features

- `asks-sudo-card` asks "Hermes needs your sudo password" with the redacted command, when Hermes stops waiting, and a `Password` field.
- `asks-secret-card` asks "Hermes needs a secret" with Hermes's reason, the variable name and a `Secret value` field.
- `asks-send` sends the typed value once and clears the field. The card becomes "You sent a password." or "You sent the secret."
- `asks-skip` sends `{ value: "" }`. The card becomes "You skipped this."
- `asks-withdrawn` closes the card when Hermes withdraws the request, with "Hermes withdrew this request."
- `asks-reconnect` keeps the card across a dropped link, shows it disabled while the link is down, and answers once it is back.
- `asks-elsewhere` plays the whole story with another client answering. The card closes with "Answered from another window."
- `asks-bridge-declined` answers the theme picker request with one `-32601`, and shows "Hermes sent a request Highwing can't show yet (theme.pick), so it said no."
- `asks-batch-declared` sends `clarify_batch: true` with the message, because the gateway said it sends batches.
- `asks-code-card` asks "Verification code for example.com" with Hermes's hint and a `Code` field shown as typed, **Skip** and **Enter code**. The vault ("Unlock {name}", `Master password`, **Keep locked**, **Unlock**) and login ("Save your {site} login?", `Email or username` and `Password`, **Don't save**, **Save and sign in**) cards are the same card. `fixtures/asks.jsonl` asks for neither, so only the tests draw them.
- `asks-batch` asks "Hermes has 2 questions", one at a time: radios for one pick, checkboxes with "Pick all that apply" for several, and **Other** for a typed line. **Next** locks an answer with `clarify.lock`, and the answer is listed above the open question with **Change**. The last question's button reads **Send answers**, and the window holds that answer until it is pressed. **Skip question** locks no answer.
- `asks-plugin-choice` asks a plugin command's one choice as "Hermes has a question", with **Send answer**.
- `asks-connect` asks "Hermes needs a connection to continue", with a row per target: "Sign in to {name}", its state, its instructions, **Open sign-in page**, **Connect** and **Skip**, then **Continue without the rest**. A target whose sign-in failed or whose link expired offers **Try again** in place of **Connect**, with no fields, and it sends `connectors.connect` with `reconnect: true` for a new link. `fixtures/asks.jsonl` has no such target, so only the tests draw it.
- `asks-jump` reads "Waiting for your answer" beside the jump control while Hermes waits on a request and you read above the live end.

## How to get to it (user POV)

- Send a request that makes Hermes run a `sudo` command, or load a skill that needs a key. In `fixtures/asks.jsonl` the one request does both, then asks for a code, a batch of questions and a connector sign-in.

## Gotchas

- At recorded timing the story takes about 15 s, so `wait settled` needs `--timeout 40000`.
- Without `--answered-elsewhere` the run never settles past the sudo request unless the window answers it.
- `--answer-here sudo`, `secret`, `clarify` and `connection` leave the window those requests. Without it `--answered-elsewhere` plays another client answering, and each card closes with "Answered from another window." after a moment.
- The fixture answers each recorded `clarify.lock` and `connection.respond` with its recorded reply, whatever the window picked, so a pick other than the recorded one still plays. A third lock of the batch, as **Change** sends, is a call the story does not expect, and fails the run.
- `answered` reads the request's method from the fixture the run plays. A method the fixture never asks counts 0.
- The line about `theme.pick` is the notice for a request refused at once. It is the only request with no card.
- The card's "Hermes waits until" time is the clock of the run, so a snapshot of it changes from run to run.
