# Password managers

Settings has a Password managers page, with one card. Its first row, Bot, picks the bot whose managers it shows, the open bot at first, from a menu of the bots the sidebar lists. Under it is one row for 1Password and one for Bitwarden, each with a badge and the one next step its state needs, from Hermes's `vault.sources` for that bot's profile, and `vault.list` only to count an unlocked manager's logins. Not installed says "Not installed on the Hermes machine." with How to install, which opens the manager's own page in the browser, and Check again. Off says "Off for <bot>." with Use with <bot> (`vault.source.set`, enabled). Locked says "Unlock it so <bot> can use its logins." with Stop using, a Master password field, Unlock (`vault.unlock`) and the one-time step Hermes has no call for, as a command to run on the Hermes machine: `hermes -p <bot> secrets onepassword token` for 1Password, `bw login --apikey` for Bitwarden. A wrong password shows Hermes's words in an alert under the row, and the field is emptied after every try. Unlocked says "Unlocked · N logins <bot> can use" with Lock (`vault.lock`) and Stop using (`vault.source.set`, disabled, which locks it too). Each change answers the bot's managers read again, and opening Settings or picking a bot reads them again. Without a connection the card says "Connect to Hermes to set up password managers.", and a Hermes without the calls says "This Hermes can't set up password managers from Highwing." The master password is never kept: it is in no draft, no log and no file.

## Sub-features

- `managers-missing` shows both managers not installed, the user's own state on a Hermes machine with neither tool, with How to install opening the manager's page and Check again reading Hermes again.
- `managers-use` turns 1Password on for Emu with Use with Emu, and it shows Locked with its service-account step.
- `managers-unlock` refuses a wrong Bitwarden password with Hermes's words, empties the field and puts focus back in it, then unlocks with the right one and counts Emu's 3 logins.
- `managers-lock` locks Bitwarden again, and `managers-stop` turns it off for Emu.
- `managers-switch` picks Research, which shows 1Password unlocked with 2 logins and Bitwarden not installed, then picks Emu again, which shows Emu's managers as the last changes left them.
- `managers-token` locks Research's 1Password, which a service account token holds open, and the row stays unlocked and says Stop using turns it off.
- `managers-offline` says to connect when Highwing has no connection, with no Bot row.
- `managers-unsupported` says this Hermes cannot set up password managers, with no Bot row.
- `managers-secret` keeps the master password out of every evidence file: each `vault.unlock` in `gateway-calls.jsonl` carries `"password":"•••"`.
- `managers-narrow` keeps the buttons and the field inside the card in a 360 px window.
- `managers-unit` holds the rules in `packages/hermes/test/passwords.test.ts` and `apps/desktop/test/password-managers.test.tsx`, not a run: each `vault.sources` row maps to one state, `local` and unknown managers are left out, logins are counted per manager, a failed `vault.list` keeps every state with its count unknown, every call names the bot's profile, and a logged `vault.unlock` holds no password.

## How to get to it (user POV)

- Press the Hermes button at the foot of the sidebar (or Ctrl+,) and pick Password managers in the Settings nav.
- Press the Bot button to pick another bot.

## Gotchas

- Settings shows only in a run with a saved connection, so these recipes use `--fake-host` with a fixture a `--fixture` run made. A `--fake-host` run cannot take `--vault` itself.
- `count` does not wait. After a click that changes a row, wait with `see` or `gone` first, as the flow does after Lock and Stop using.
- Every row's buttons and field carry the manager's name (`Unlock Bitwarden`, `Bitwarden master password`), since both rows can be locked at once. The Bot button is named `Bot <name>`.
- The fake's unlocks last until the run ends and are kept per profile. Hermes itself drops an unlock after 30 idle minutes (agent/vault_backends/unlock.py:29), which no run waits for.
- `fixtures/vault/managers.json` holds a master password in plain text, so a run that names it with `--vault` writes it to that run's `fixture-edited.jsonl`. Type it only in a later run that plays the copy, as the recipes do, or that run's leak check fails on its own fixture.
