# Routines

The details panel of [Bot details](./bot-details.md) has a Routines tab beside Details. It lists the cron jobs Hermes runs for the bot, read with `cron.manage` action `list` under the bot's profile with paused jobs included. Each row shows the job's name, without the `[bot:<name>] ` tag an older Hermes puts in front of it, and when it runs in plain words, or Paused. Each row has Pause or Resume and Delete…. Each control is one `cron.manage` call with the job's id, and the row shows the job Hermes answers with. Delete… asks first. Past runs opens the routine's 20 newest runs under its row, read from Hermes's `GET /api/cron/jobs/<id>/runs` over HTTP. Each run shows its state in words, its time, how long it took when Hermes says, and the reason a failed, cancelled or missed run gives. Open run shows the run's chat with no composer. An open Past runs list is read again every 15 s, because Hermes sends `cron.changed` only for the gateway's own profile, and a failed reread keeps the runs it shows. The list is read again on every `cron.changed` and every new socket while the tab is shown. Hermes runs the jobs, and Highwing keeps no scheduler.

## Sub-features

- `routines-list` lists each job with its schedule in plain words or Paused, and asks `cron.manage` once when the tab opens.
- `routines-empty` tells the user to ask the bot in a chat when the bot has no jobs.
- `routines-unsupported` shows Hermes's refusal in words when it has no `cron.manage`.
- `routines-runs` lists a routine's past runs with state, time, duration and reason, opens one read-only, and shows Hermes's refusal for a routine whose runs route answers 404.
- `routines-edits` runs a routine now and changes its schedule through Hermes's REST routes, shows Hermes's verdict on the run, Hermes's refusal of a schedule in the field, and Hermes's next run after a save. Run now is not offered on a paused routine, and neither control is offered when the bot's run list route does not answer.
- `routines-controls` pauses and resumes a job, backs out of a delete by Escape and by Cancel with the panel left open and focus back on Delete…, then confirms one, and each row shows Hermes's answer.

## How to get to it (user POV)

- Open a bot's chat, click the bot's name in the top bar, then click Routines.

## Gotchas

- Run now and the schedule go over HTTP as well, so `called` cannot see them. The fixture's REST layer answers them from `cron.rest` by job id, and it is a different fake from the gateway's cron store, so a later `cron.manage` list shows the stored job again. The row shows Hermes's answer until the next list read. `apps/desktop/test/routine-edits.test.ts` covers the request each sends.
- The next run after a save is Hermes's `next_run_at` in the window's local zone. The schedule words are in the job's own zone, so the two can show different clock times.

- Past runs come over HTTP, not the socket, so `called` cannot see the runs read. The fixture's REST read serves `cron.history` by job id, and `packages/hermes/test/fixture.test.ts` covers it. Times are shown in the run's local zone, and `count` does not wait, so `see` a run's state before counting the list.

- The scripted gateway pushes `cron.changed` only after a control, so a recipe cannot show a job that changed elsewhere. `packages/hermes/test/routines.test.ts` covers that push.
- `--bound` launches into a chat with no bot, so the panel cannot be opened there. `packages/hermes/test/routines.test.ts` covers a bound socket's refusal.
